# 05 DICT 사전 — 15쌍 초안 (본인 검수용)

- 형식: 현장 용어 ↔ 개발 용어 · 근거(어디서 겪은 일인지 — 화면의 note로 쓸 수 있음)
- 숫자는 넣지 않음(화면 숫자는 metric에서만). 고치거나 빼거나 순서를 바꿔 주면 그대로 반영한다.
- 기존 5쌍(지시서 예시)은 맨 아래에 그대로 둠.

| # | 현장 | 개발 | 근거 |
|---|---|---|---|
| 1 | 클레임 유형 분류표 | 라벨 체계(taxonomy) + 다빈도 집계 쿼리 | 김치 공장 클레임 재분류(유형·공정·원료·계절) |
| 2 | 다시 안 나게 해 주세요 | 원인별 관리기준 = 재발 방지 규칙(rule) + 회귀 테스트 | 클레임 원인별 관리기준 재설계 |
| 3 | 절임 조건표(품종·계절·날씨별) | 조건부 파라미터 테이블(feature → setpoint) | 절임조건 데이터화 |
| 4 | 염도 편차 관리 | 허용 오차(tolerance) + 이탈 알림 | 절임염도 편차 관리 |
| 5 | 금속검출기 테스트피스 점검 | 정기 회귀 테스트 — 테스트피스가 테스트 케이스 | 금속검출기 검증 체계 |
| 6 | 표시사항 검토 | 규칙 기반 검사 + 근거 조문 검색(RAG) | 표시사항 검토 표준화 · 06 PoC 후보 |
| 7 | 로트 추적 | 추적 ID(trace id) + 이력 테이블 조인 | HACCP 이력 관리 |
| 8 | 선입선출 | FIFO 큐 | 원부재료 재고 운영 |
| 9 | 원료 수불부 | 입고·출고 이벤트의 합(이벤트 소싱) | 원부재료 재고·구매 |
| 10 | 개선조치 기록 | 인시던트 리포트(포스트모템) | CCP 이탈 시 개선조치 |
| 11 | 병목 공정 | 처리량을 막는 한 지점 — 한 변수씩 바꾸고 재측정 | 반자동화 라인 ↔ Metabole 부하 테스트 |
| 12 | 일 생산능력 | 처리량(throughput) | 톤/일 ↔ RPS |
| 13 | HACCP 재인증 | 배포 전 릴리스 게이트(체크리스트 통과해야 출고) | 공장 이전 후 재인증 |
| 14 | 설비 배치도(Layout) | 아키텍처 다이어그램 + 마이그레이션 계획 | 공장 이전 Layout 설계 |
| 15 | SKU별 원가 | 제품 단위 비용 집계 모델 | SKU 원가·손익 관리 |

## 기존 5쌍 (지시서 예시, 현재 화면)
| 현장 | 개발 |
|---|---|
| CCP 한계기준 | validation rule + alert threshold |
| 한도견본 | 입고 검수 기준 데이터셋 |
| Audit 연 80회 | 평가셋 + 재현 가능한 검증 |
| 작업일지 | 이벤트 로그 스키마 |
| 라인이 자주 서요 | downtime_event + 정지사유 코드(작업자가 실제로 입력할 3개만) |

## 참고
- 01 GAP은 사전 앞 6쌍을 좌우 대비로 보여 준다. 순서를 정할 때 GAP에 보일 6쌍을 맨 앞에 두면 된다.
- 기존 "Audit 연 80회", "3개만"에는 숫자가 들어 있다. 이력서 근거(Audit 연 80회 이상)가 있으니 유지해도 되고, 규칙을 엄격히 하려면 "Audit"·"정지사유 코드(실제로 입력할 것만)"로 바꿀 수 있다.
